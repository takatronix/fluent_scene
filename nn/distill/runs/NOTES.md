## 重要な発見: 設計書レシピそのままでは白紙崩壊する

v1 (L1+sobel, lr2e-3, 設計書どおり) は step200 で既に「全画素=紙」に崩壊し
20kまで一度も脱出しなかった (生徒出力 min 1.000)。線は画素の~3%しかなく
「常に白」が強い局所解 + sigmoid飽和で勾配消失が真因。

1500step×3案のベイクオフ:

| 案 | pixel項 | lr | 教師インク画素での生徒平均 | 判定 |
|---|---|---|---|---|
| A | L1 (設計書) | 5e-4 | 1.000 (完全死) | lr減では救えない |
| B | BCE(ロジット) | 2e-3 | 0.787 | ✓ 採用 |
| C | BCE(ロジット) | 1e-3 | 0.760 | ✓ |

対処 = pixel項を L1 → BCE(ロジット直結、飽和しても勾配 p−t で生きる) に
変更 (train.py --loss bce が新既定)。sobel項・構造・optimizer・cosineは設計どおり。
ONNXグラフは不変 (sigmoidは推論グラフに残る)。

## v2 本番 (採用モデル)

- 20k steps, batch16, crop384, BCE+0.5*sobelL1, AdamW 2e-3 cosine, COCO val2017 5000枚
- 48分 (0.15s/step, データローダ律速でGPU util ~70%)
- 最終 train loss 0.1937 / 固定val4枚: 教師との L1 0.0430
  (推移 5k:0.0468 → 10k:0.0445 → 15k:0.0427 → 20k:0.0430)
- チェックポイント: runs/v2/student.pt (425KB)

## エクスポータの罠 (export_onnx.py に修正済)

- torch≥2.9 の新(dynamo)エクスポータは opset_version=17 を無視して 18 を出し、
  重みを .onnx.data に分離する → `dynamo=False` で旧経路に固定
- 旧経路+onnxconverter_common の fp16 変換は設計書どおり無名ノード命名が必要

# 第2ラウンド (同日): 濃さ修正 + 太いイラスト調 tiny_ink

## 発端: 実写で「教師と目視同等」が甘い判定だった

オーナーがwebカメラで教師と並べたところ、生徒の線が明らかに薄くソフト。
学習中の計測でも出ていた (教師のインク画素で 教師0.369 vs 生徒0.561 =
約1.5倍明るい) が、COCO検証画像では気にならず見逃していた。

真因: 線は画素の約4%しかないため、BCEが紙側に支配される。1500step×3案の
較正で ink-weight (線画素へのBCE重み) を決定:

| ink_weight | 線上の濃さ 生徒/教師 | 差 | ink率 生徒/教師 |
|---|---|---|---|
| 0 | 0.762 / 0.387 | +0.375 | 0.22% / 4.71% |
| 4 | 0.615 / 0.391 | +0.224 | 1.46% / 4.29% |
| **10** | **0.580 / 0.393** | **+0.187** | 2.19% / 4.68% |

→ `--ink-weight 10` を採用 (train.py に実装)。v3 = 鉛筆版の焼き直し。

## tiny_ink: 非商用モデルを使わずに「太いイラスト調」を作る

オーナーが気に入った portrait sketch (ink) は AnimeGANv3 = 非商用。設計書§2
どおり教師にはできないので、教師を自作した (ink_target.py)。

失敗した案も記録する:
- **gpen (2値太線)**: ターゲットは良いが 105k が急峻な境界を再現できず、
  黒い太線ではなく灰色のにじみになった (生徒ink率 4.7% vs 目標 12.6%)
- **輝度によるベタ塗り**: 「影」ではなく「暗い場所」を塗るため、絵ではなく
  2値化写真になった。PortraitSketchのベタは意味理解の産物で閾値では代替不可

効いた設計 (portrait_ink):
1. **教師に入れる前に写真をガイデッドフィルタで平滑化** (r=6, eps=0.05)。
   質感が最初から無ければ教師は線を引かない = 単純化が無料で手に入る。
   これが「イラストらしさ」の正体で、生徒の入力は素の写真のまま
2. ヒステリシス (0.50→0.70, 8回成長) で線を繋ぐ。単純な閾値だと破線になる
3. 3px膨張 + 軽いアンチエイリアス (純粋な階段関数は105kには学習不能)

結果 (20k): 生徒ink率 18.7% / 目標 14.0%、L1 0.0975。gpenの灰色化は回避。

## 硬化カーブ: 生徒のグレーは不確実性なので読み直す

2値ターゲットに対し生徒の出力は境界がぼやける。`clip((v-0.5)*3+0.5)` を
かけると中間グレーが 27.0% → 8.0% (目標 8.3%) と一致し、L1 も 0.0975 →
0.0800 に改善。小手先の補正ではなく、蒸留した答えの読み出しと解釈できる。
export_onnx.py の `--harden 3` でONNXグラフに焼き込み済み (使う側は何も不要)。
鉛筆版には掛けない — あちらのグレーは実際の筆圧の濃淡なので潰すと壊れる。

## 罠: この画風は解像度依存

線の太さ(3px)も平滑化半径(6px)もピクセル固定なので、推論解像度で見え方が変わる:
384px ink率13.1% → 512px 10.7% → 768px 8.1% → 1024px 6.7%。
1024pxだと「太いイラスト」ではなく「細かい線画」になる。anime.html は
tiny_ink 選択時に推論サイズを512へ自動で合わせる。
