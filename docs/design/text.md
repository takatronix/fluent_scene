# テキスト描画の設計（0.20.0〜）

fluent_scene の文字は「どの大きさでも・どの変換でもくっきり」「CJK を何千字でも」
「毎フレーム数字を変えても安い」を同時に満たすように作り直した。
旧実装（`src/text_atlas.cpp`）は 26 px 固定で 32×32 セルにラスタライズし、
他のサイズはそのビットマップを拡大縮小していたため、OBD ビューの大きな数字が
ぼやけ、32 px を超える字形はセルで切れていた。

API は [docs/api/text.ja.md](../api/text.ja.md)、レシピは cookbook の「文字」節。

## 1. 方式の選択（要約）

| 案 | 判断 |
|---|---|
| 固定サイズのビットマップを拡大（旧） | 拡大でぼける。不可 |
| MSDF（msdfgen 方式） | 角は鋭いが RGB/RGBA で 3〜4 倍のメモリ、エッジ彩色の生成が重く、CJK の重なり輪郭で破綻しやすい。縁取り・太字化には別途真の距離（MTSDF）が要る |
| **単チャンネル SDF ＋ サイズ別バケット ＋ 小サイズはビットマップ（採用）** | 下記 |

採用した構成:

- **小さい正立文字（画面上 ≤ 32 px、回転・非一様拡大・縁取りなし）**:
  その**画面ピクセルサイズちょうど**（¼ px 刻み）で FreeType の light hinting
  付きラスタライズ。ベースラインを整数画素、x を ¼ 画素（4 位相のサブピクセル
  配置）にスナップ。最も鮮明。
- **それ以外（大きい・回転/拡大・縁取り・合成太字）**: 符号付き距離場（SDF）を
  **サイズバケット**（24/32/48/64/96/128/192/256 px、√2 刻み）で生成し、
  画面サイズに最も近いバケットから描く。拡大率は最大でも約 1.17 倍なので、
  単チャンネル SDF の弱点（角の丸まり）は見えない。アンチエイリアス幅は
  画面上ちょうど 1 px（シェーダは微分ではなく CPU が渡す「px/テクセル」比を
  使う — WGSL の uniformity 制約を回避し、全バックエンドで同一の絵）。
- 単チャンネルなので R8 1 バイト/テクセル。MSDF の 1/3〜1/4 のメモリで、
  距離が真の距離なので **縁取り（外/内/中央）と合成太字は閾値をずらすだけ**。

## 2. フォント（`src/text/font_library.*`）

- プロセス共有のレジストリ。ファミリ（`sans` / `serif` / `mono` / 任意名）×
  ウェイト × イタリック。既定は Noto Sans CJK JP Regular/Bold、Noto Serif CJK、
  Noto Sans Mono CJK（無ければ DejaVu）。既定フォントは**遅延オープン**
  （ファイルは mmap、使われたファミリだけ開く）。
- `registerFont(family, file, weight, italic)` / `registerFontData(...)`（wasm は
  `fs_register_font` でフェッチしたバイト列）。
- 字形が無い文字は既定ファミリへフォールバック。どのフォントにも無い文字は
  決定的な中抜きの箱（wasm サブセットの .notdef は空なので自前で生成）。
- 本物の Bold があればそれを使い、無ければ SDF の閾値（ビットマップは
  `FT_Outline_EmboldenXY`）で合成太字。イタリック面が無ければ 12° の合成斜体
  （ラスタライズ時に輪郭へ shear）。
- 整形は HarfBuzz（hb-ot、font units、ヒンティング無し）なので advance は
  サイズ非依存 — 1 回の整形で全サイズに使え、サブピクセル配置と矛盾しない。
  カーニング等は HarfBuzz 既定の機能（kern/liga/calt/ccmp/mark）。

## 3. SDF 生成（`src/text/sdf.*`）

FreeType 内蔵の `sdf` レンダラは 64 px の漢字 1 字に 17 ms（`bsdf` でも 3 ms）
かかり、CJK の動的生成には遅すぎた。自前のハイブリッドにした:

- 縁から 2.5 テクセル以内（アンチエイリアス・細い縁取り・太字が読む範囲）は
  **輪郭を線分化して厳密な距離**を書く。
- それより遠くは被覆ビットマップを種にした Felzenszwalb の二乗距離変換
  （TinySDF と同じ近似）。
- 符号は同じ輪郭の被覆から取るので、重なった輪郭も正しく union される。

| | 時間/字（64 px） | 縁付近の誤差（FreeType sdf 比、平均） |
|---|---|---|
| FreeType `sdf` | 16.8 ms | — |
| FreeType `bsdf` | 3.0 ms | — |
| TinySDF 方式のみ | 0.13 ms | 0.18 テクセル |
| **採用（ハイブリッド）** | **0.18 ms** | **0.045 テクセル** |

符号化は `255 × clamp(0.5 − d / (2·spread))`、spread = バケットの 3/16。
→ 縁取りは最大約 0.17 em まで。

## 4. 動的アトラス（`src/text/glyph_atlas.*`）

- 固定グリフ集合なし。初めて見た字をその場でラスタライズ（500 字の新しい漢字で
  SDF 54 ms、16 px ビットマップ 2.4 ms — farm3）。
- R8 のページ（既定 1024²、最大 16 ページ = 16 MB）にシェルフパッキング、
  タイル間 1 テクセルの隙間。
- **上限付きメモリ**: 全ページが埋まると、**現在のフレームで使っていない**
  ページのうち最も古く使われたものを消して再利用（ページ単位 LRU）。
  今フレームで使ったページは決して消さないので、描画中の参照は常に有効。
  それでも足りない（1 フレームに 16 ページ超の字）ときは追加せずに失敗を数える。
- ページは「変更された行の帯」だけを GPU へ送る（Vulkan はフレーム途中の
  `vkCmdCopyBufferToImage`、WebGPU は `queue.writeTexture`）。

## 5. レイアウト（`src/text/text_layout.*`）

純関数: `TextContent` → 配置済みグリフ + `TextMetrics`。

1. スパン → 文字ごとのフォント選択（フォールバック）→ (スパン, フェイス) ごとに整形
2. 文字単位の「ユニット」と改行機会: 空白の後、CJK の境界（禁則: 行頭に
   `、。」）ー` 小書き仮名など、行末に `「（` などを置かない）、ハイフンの後
3. 貪欲な行分割（収まらない単語は文字境界で強制改行）、`max_lines` /
   `max_height` で切り詰め、`ellipsis` で「…」
4. 自動縮小: `min_size` 以上で収まる最大の倍率を二分探索（整形は 1 回だけ）
5. 等幅数字: OpenType `tnum` を要求し、さらに数字の advance を最大幅に揃える
   （Noto CJK は tnum を持たないため。どのフォントでも数字が揺れない）
6. 行の高さ: フォントの hhea（ascender + descender + lineGap）、または
   `line_height × size`（CSS の half-leading と同じ配り方）
7. `Align` × `VAlign`（top / middle / baseline / bottom）で配置

**互換**: 既定値（1 行、`position` = 1 行目の行ボックス左上）は旧実装と同じ規則。
ベースラインは旧実装（26 px で丸めた ascender の比率）より最大 0.03 em 上に
なる（丸めをやめて正確な値にしたため）。`\n` は改行になった（旧実装は箱）。

## 6. 描画（`src/text/text_engine.*` ＋ 各バックエンド）

- テキスト 1 つ = ペイント（スパン色）ごとに
  1. RG マスク（R = 塗り、G = 塗り∪縁取り）へグリフごとの被覆を MAX 合成
     （重なった字形が二重に濃くならない）
  2. `text_composite` でペイントを適用: 塗り色（またはグラデーション）、
     縁取りの輪、**輝度依存のコントラスト補正**（sRGB 空間合成で明色文字が細く、
     暗色文字が太く見える問題を Skia/DirectWrite 流に穏やかに補正）
- 計算本体は `include/fluent_scene/shared/text_shared.h`（GLSL∩C++）で、
  CPU・Vulkan・WebGPU が同じ式を使う。実測: Vulkan と CPU の差は PSNR 53〜72 dB、
  wasm CPU は native CPU とビット一致、WebGPU は PSNR 62〜81 dB。
- 影はレイヤーのシルエット影（既存）、グローは「オフセット 0 の影」。
- キャッシュ: レイアウトは内容のキーで、各テキストのクアッド列は
  （変換・色・アトラス世代）が同じなら前フレームのものを再利用。
  数字が毎フレーム変わっても再整形は数文字、ラスタライズは各数字の初回だけ。

## 7. wasm

- `--jp`（既定）は Noto Sans JP Regular と **Bold** のサブセット（各約 1 MB）を
  埋め込む。wasm は 4.26 MB → 5.47 MB（`--no-bold` で Bold 無し = 合成太字）。
  他のフォントは実行時に `fs_register_font` で読み込める。

## 8. 計測（farm3, RTX 5090 / Ryzen）

`examples/text_bench`（1920×1080、2,000 字 + 毎フレーム変わる数字 10 個）:

| | 文字なしのフレーム | 文字ぶんの追加時間（定常） | 数字が毎フレーム変化 |
|---|---|---|---|
| Vulkan（新） | 32 ms ※ | +2.2 ms | +1.0 ms |
| Vulkan（旧） | 33 ms ※ | +1.9 ms | +0.4 ms |
| CPU（新） | 18 ms | +9.9 ms | +11.5 ms |
| CPU（旧） | 17 ms | +10.5 ms | +10.3 ms |

※ 1920×1080 の読み戻し待ちが支配的（GPU 使用率 0%）。文字ぶんは旧実装と同程度
で、画質は全サイズで向上。atlas 構築: 新しい漢字 500 字 = SDF 54 ms / 16 px
ビットマップ 2.4 ms。

  同フレームのページを退避しないこと）、SDF 精度（場から復元した被覆 vs
  FreeType の厳密ラスタ: PSNR 37.7 dB、下限 30）、レイアウト（禁則・折返し・
  省略・自動縮小・等幅数字・縦揃え・改行・スパン）、Layer API
- `golden_tests`: `text` / `text_styles` / `text_transforms` に PSNR ≥ 38 dB・
  SSIM ≥ 0.98 の下限（Vulkan も同じゴールデン）
- `wasm/tests/text_abi.test.mjs`: wasm ABI
- `tests/text/`: 10〜300 px・明暗・回転/拡大のプローブ（CPU / Vulkan:
  `render_probe.sh`、WebGPU/wasm: `probe_web.mjs`）
