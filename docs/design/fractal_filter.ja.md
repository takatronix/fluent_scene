# fs_fractal — 永遠に変化し続けるフラクタル飛行 設計書

- 状態: **凍結** (2026-08-16)
- モードID: `FS_FRACTAL = 39` (37/38 は並行作業の ntsc/crt が先取)
- 公開名: `fractal` / 型名 `Fractal`

## 1. 目的

「疾走感のある高解像度フラクタルが自己変化し続ける。どう変わるかわからない。
同じ見た目・同じ状態が二度と来ない。美しく変化し続ける」(オーナー要望 2026-08-16)。

視聴は無限時間を想定する。乱数もフレーム間状態も使わず、**`time` の純関数**として
実装する — t=0 で静止しゴールデンテスト可能、同じ t を与えれば同じ画が出る
(fs_lsd と同じホスト駆動 time 規約)。

## 2. 参照作品と、そこから取る「機構」

同じものは作らない(オーナー指示)。コードは一切移植せず、以下の**一般技法**だけを
独自の構成・定数で合成する。

| 参照 | 取る機構 | 権利上の扱い |
|---|---|---|
| Shadertoy ltBcRc (円反転IFS) | 非通約多倍音のパラメータドリフト / **反復深度差のRGB虹彩** | 技法のみ |
| iq Apollonian (4ds3zn) | orbit trap の一人三役 (材質色・縁色・擬似AO) | 全権留保 — 技法は本人の教育記事に公開、コードは不可視扱い |
| Syntopia KIFS Menger | 無限タイル折り畳み / 前進カメラ / 非線形パース / **DE内時間変形** / 軽量マーチ(低ステップ+fudge+jitter+ステップ数AO) | 技法のみ (fractalforums/blog公開) |
| "Happy Accident" (CC0) | **発光アキュムレータ** (`col += 色/距離`、breakしないマーチ) = ぬめっと質感 / tanh トーン圧縮 / 偽環境反射+スペキュラ | CC0 だが方針統一で独自実装 |

KIFS 自体は Knighty (fractalforums 2010) 公開の一般技法。sphere tracing は Hart (1996)。

## 3. 「二度と同じ状態にならない」の数理

全ての時変パラメータは **互いに通約しない周波数の正弦和** で駆動する:

```
osc(t; f1..f3, φ) = sin(f1·t + φ) + sin(f2·t + 2φ) + sin(f3·t + 4φ)
```

周波数比が無理数なら軌道はトーラス上で稠密 = 厳密に非周期。これがフラクタルの
カオス感度 (パラメータ微小変化 → 構造の指数的組み替え) と掛け合わさり、
「似た雰囲気は保つが同じ画は二度と出ない」が保証される。駆動先:

1. fold 回転角 ×2 (DE内時間変形 — 構造そのものが組み替わる)
2. KIFS スケール S の呼吸 (≈2.5–3.1)
3. カメラの横揺れ・ロール
4. 非線形パースの深さ (0 ↔ ワームホール)
5. パレット位相 (色相の季節)
6. glow 量の潮汐

**永遠性の工学**: 空間は全軸 2 単位でタイルされ構造は z に厳密周期的なので、
カメラ z は `mod(speed·t, 2)` で折り返す — float32 の精度劣化なしに文字通り
永遠に飛べる。回転角は t に線形だが sin 引数の float32 誤差は t=10⁵s (約28h)
でも位相 10⁻⁴ rad 級で知覚不能。

## 4. 構成

### 4.1 DE (距離推定) — 自己変形KIFS

```
p ← カメラ空間の点
z = abs(1 − mod₂(p))            # 無限タイル折り畳み (fract-free 表記)
for n in 0..6:
    rot(z.xy, A₁(t))             # 時変 fold 回転 (自己変形の心臓)
    z = abs(z); sort-fold(z)     # 万華鏡 fold (降順ソート)
    rot(z.yz, A₂(t))
    z = S·z − Off·(S−1)          # スケール+オフセット, z軸は折り返し
    trap 記録 (§4.3)
d = (length(z) − r₀)·S⁻⁽ⁿ⁺¹⁾ − ε
```

Off は独自定数 (実装時に美観チューニング、初期値 vec3(1.05, 0.97, 0.48))。

### 4.2 マーチ — ハイブリッド (硬い表面 + ぬめっと発光)

- 44 ステップ、`t += d·0.72`、ピクセルハッシュの開始ジッターでバンディング隠し
- 各ステップ `glow += palette(q, 行程)/max(d, ε)` を積分 (breakしない質感成分)
- `d < 0.001·t` で表面確定 → 4点四面体法線、2灯照明 (暖色キー + 寒色フィル)、
  ステップ数AO × trap AO、reflect による偽環境反射 + スペキュラ
- 出力 = 表面色·フォグ + glow·潮汐、最後に `tanh` トーン圧縮
- レイ方向は行程距離に比例して回る (非線形パース、深さは osc 駆動)

### 4.3 着色 — orbit trap + 反復深度差の虹彩

trap は `min(|z|)` と軸距離を追い、**深度 n, n−1, n−2 の3値を R/G/B の位相差**
として使う (ltBcRc の2D機構を 3D KIFS trap へ移植 — 独自の合成)。等値面に
沿って薄膜干渉状の虹色の縁 = 「光彩」が出る。ベースは iq-cosine パレット
(独自係数、位相は osc 駆動)。

### 4.4 パラメータ (スロット順 = filters_def.h)

| slot | 名前 | 既定 | 意味 |
|---|---|---|---|
| 0 | flight | 1.0 | 前進速度倍率 (0 = 静止浮遊) |
| 1 | time | 0.0 | ホスト駆動秒。0 = 静止フレーム (ゴールデン) |
| 2 | morph | 1.0 | 自己変形の深さ (fold 角ドリフト振幅) |
| 3 | glow | 1.0 | 発光積分の量 (0 = 硬い表面のみ、大 = ぬめっと) |
| 4 | blend | 0.0 | ソース映像の混入 (0 = 純生成、1 = 映像がパレットを染める) |

`blend > 0` で FS_SAMPLE(uv) がパレットを変調 — ビデオフィルタとしても機能する。

## 5. パリティとテスト

写像は連続 (分岐は max/min と等価) だがリャプノフ増幅は不可避。LSD/notebook と
同じ **waiver 型ゴールデン**: `g_max_diff_limit = 255` に緩め、over_ratio が
守る。シーンは t=0 既定 + time/morph/glow/blend 変化の 5 タイル。

CPU コスト見積: 44 step × 7 fold ≈ 12 kflop/px → ゴールデン解像度で 1–2 s。
実用リアルタイムは GPU (Vulkan / WebGPU) 専用と割り切る。

## 6. shim 拡張

glsl_compat.hpp に GLSL 標準関数を追加: `abs(vec3)`, `normalize(vec2/vec3)`,
`tanh(float)`, `vec3 operator-=`。mat2 は導入しない (回転は fs_lsd と同じ
dot 展開の家風)。swizzle 不使用。

## 7. デモ (wasm/fractal.html)

- WebGPU バックエンド必須 (`fs_webgpu_init` → `fs_render_webgpu` の
  zero-readback 経路)。非対応ブラウザは CPU で 320×180 に落として励行
- シーンはカメラ入力なしの純生成 (共有しやすい)。UI は lsd.html の家風:
  flight / morph / glow スライダー + フルスクリーン
- time は rAF の経過秒をそのまま流す

## 8.5 飛行経路の空域設計 (Phase 3, 設計中 — 8/16朝)

カメラ衝突は後付け回避(DEクリアランス操縦: 二値→ソフトバンド)では解決しな
かった(オーナー判断で撤去: 二値は境界チャタリング、回避挙動自体が汚い)。
**回廊シーキングv1**(前方2断面×3×3のsoftmax重心へ横位置を導出)も試作した
が、受け入れ計測で優位を示せず不採用(スクラッチパッドの corridor_block.txt
に保存)。

**計測の教訓**: 1秒刻み静止スナップの画像指標(分散/コヒーレンス比)では衝突
は写らない — 連続運動中の現象。次フェーズはまず**fs_fractal_probe のwasm
export**(カメラ位置のDE値を直接返す)を作り、飛行に沿ったクリアランス時系列
を物差しにする。

**Phase 3 実測結果 (8/16朝、DE直接測定ハーネス)**:
- 現行カメラは悪epochで**飛行時間の73%が壁内**(e=1489、連続97秒)。これが「バグりモード」の定量値
- 決定的発見: **悪epochではタイル断面全体が構造で埋まり、回廊が存在しない**
  (7×7×5点探索でも空きゼロ)。(x,y)の経路計画では救えない — 答えは「**空いて
  いる時代だけを飛ぶ**」(epoch選別)
- 空きが存在するepoch(e=9026)では回廊追従が有効: 壁接触0.4→0.0%、近接4→0.5%
- 対処済み: クリアランススイープ(0..3000s、DE>0.06、48%が合格)を画像品質カタ
  ログと交差 → **二重保証の着地カタログ37区間**(fractal.html/index.htmlに反映)

**残フェーズ**(相方と合同):
1. fs_fractal_probe の wasm export 化(ハーネスは scratchpad/clearance.cpp)
2. 証明済み空域内での(x,y)回廊追従 — フィルタへの経路注入チャネルは
   fs_face 方式の制御ストリップ画像(パラメータ5枠は満杯のため)
3. 退屈レスキュー(画像分散+コヒーレンス比)は保険として存続
